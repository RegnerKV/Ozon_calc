## Установленные изменения

Свежая схема содержит предупреждение об отключении `/v3/finance/transaction/list` и `/v3/finance/transaction/totals` **08.09.2026**. В качестве замены перечислены:

- `POST /v1/finance/accrual/by-day` — начисления за день;
- `POST /v1/finance/accrual/types` — справочник типов;
- `POST /v1/finance/accrual/postings` — детализация по номерам отправлений.

Приложение использует первые два: дневной список содержит начисления с привязкой к отправлению, товару, общие и контейнерные услуги. Справочник используется для названий услуг. Отдельное получение по номерам отправлений пока не вызывается — иначе можно задвоить те же начисления.

Для `/v2/posting/fbo/list` и `/v3/posting/fbs/list` свежая схема указывает отключение **31.08.2026** и замены:

- `POST /v3/posting/fbo/list`;
- `POST /v4/posting/fbs/list`.

Это согласуется с пользовательским ответом Ozon `obsolete method cannot be used` для прежнего FBO и 404 для прежних финансов/FBS.

## Обновлённые контракты

Дневные начисления: запрос `{date: "YYYY-MM-DD", last_id: ""}`, затем тот же date и last_id ответа. По схеме идентификатор страницы живёт 15 минут. Отсутствие last_id/пустой last_id завершает день. Указана ранняя дата 01.01.2022. Запросы последовательные. Старые page/page_size и обёртка result не применяются.

Ответы дневного списка содержат `accruals`, `last_id`; итог каждого начисления — `total_amount` с amount/currency. Идентификатор — accrual_id. Сохраняется именно итог один раз. Вложенные commission/bonus/coinvestment, delivery/services и другие fees объясняют его состав и не прибавляются к нему ещё раз. Неподдерживаемая валюта, дата, категория, повтор ID или неподвижный курсор останавливают обновление.

Списки FBO v3/FBS v4: cursor, sort_dir=ASC, filter.since/to, limit; ответ верхнего уровня postings/has_next/cursor. Никаких offset/dir старого формата. Следующая страница требует новый непустой cursor. Деньги в товарах могут быть объектами amount/currency. Покупательские адреса и имена отбрасываются.

## Границы проверки

Новые структуры протестированы на синтетических примерах, соответствующих обеим копиям схемы. Реальное успешное подключение размещённого приложения с пользовательским ключом ещё нужно подтвердить. Тарифные ограничения и фактические права конкретного ключа нельзя считать установленными по отсутствию предупреждений в схемах.

API-данные по-прежнему сохраняются для сверки и не добавляются к бухгалтерским операциям Excel. Следующий шаг после успешной загрузки — сверить итог периода с исходным отчётом и согласовать источник расчёта прибыли.
