# Ozon Profit 💎

Локальное приложение для учёта предварительной прибыли магазина украшений: русский интерфейс, Excel, SQLite, история себестоимости. Данные хранятся отдельно от программы.

## Загрузить ваши отчёты

1. Откройте **Импорт отчётов Ozon**.
2. Выберите отчёт начислений, файл себестоимости и отчёт реализации. Предыдущий расчёт можно добавить четвёртым файлом для сравнения.
3. Проверьте предложенное сопоставление изделий. Для «Наличника» используется синий вариант, подтверждённый владельцем. Для обеих «Малин» берётся стоимость «Рыбы» из вашего файла — с обязательной отметкой оценки. Цены не зашиты в программу.
4. Выберите дату действия себестоимости и предварительную налоговую базу. Основной вариант сверки — только реализация. В настройках доступны другие варианты.
5. Проверьте предварительный результат, отметьте полноту финансового отчёта и нажмите **Загрузить отчёты и пересчитать**.
6. Откройте **Обзор**, выберите период. При следующем запуске первоначально предлагается последний импортированный период.

Оригинальные финансовый отчёт и реализация сверяются по каждому артикулу: суммы, количество продаж/возвратов, программы партнёров. При расхождении автоимпорт блокируется. Предыдущая сверка читается как данные и не добавляется к доходам.

Сложный лист «Украшения» распознаётся по блокам **С упаковкой:**. Листы закупки материалов не используются вместо полной стоимости изделия. Неизвестные новые типы начислений и изменившиеся заголовки останавливают импорт вместо молчаливого угадывания. Для других таблиц есть раздел **Загрузка Excel** с ручным соответствием столбцов и редактируемым просмотром строк.

## Расчёты и ограничения

Начисления = сумма финансовых строк со знаком. Предварительная прибыль = начисления − себестоимость − расчётный налог. Реклама и услуги уже включены в финансовые начисления; повторно их не вычитают. Положительный возврат эквайринга уменьшает расходы, а не увеличивает выручку продаж. Баллы и программы партнёров — отдельные виды финансовых операций.

Все суммы считаются Decimal без промежуточного округления себестоимости до копеек. Округление — при отображении. Справочник хранит дату действия стоимости; новая дата сохраняет историю, запись на ту же дату заменяет значение. Неизвестная и примерная себестоимость видна отдельно, в том числе у товаров, по которым есть только расходы и нет продаж.

Для налогового резерва доступны: реализация; реализация + программы партнёров; реализация + баллы; реализация + баллы + программы партнёров; пользовательский вариант по итоговым начислениям. Ставка изначально 4%, её можно изменить. В ручном импорте без настройки исторический вариант — реализация + баллы, в автоматическом импорте база явно выбирается пользователем. Выбранная база показана в настройках; ни одна не выдаётся за подтверждённое начисление ФНС. Налоговая трактовка баллов, партнёрских выплат, компенсаций и собственный налоговый статус требуют отдельной проверки. Компенсации автоматически в стандартную базу не включены.

В основной сверке используется прежняя методика налога только с реализации, без баллов и партнёрских выплат. Арифметика сверена с предоставленными файлами; независимая правовая проверка налоговой базы не завершена: доступ к официальной статье seller.ozon.ru был отклонён сетевым прокси (403). Сами финансовые результаты и отчёты не включены в исходники.

Продажа списывает стоимость на дату начисления выручки. Возврат выручки уменьшает начисления и налоговую базу, но сам по себе не восстанавливает стоимость в запасе. Для пригодного физически возвращённого изделия нужна отдельная нулевая операция `restock` с исходным отправлением и артикулом; она восстанавливает стоимость исходных продаж по очереди. Суммарное восстановление сверх количества продаж не увеличивает прибыль и помечается проблемой. Физическое состояние и правильность связи возврата с заказом проверяет пользователь.

Учёт ведётся по датам начислений, не по когортам заказов. Часть расходов может относиться к другим месяцам. Общие расходы без артикула и расходы без достоверного номера отправления не распределяются по заказам автоматически. Поэтому результат отдельного заказа до общих расходов не является его окончательной чистой прибылью. Отрицательная налоговая база не создаёт отрицательный резерв; при возвратах итоговый налог периода может отличаться от суммы построчного налога.

Прибыль пока **предварительная**: даже совпавшие отчёты не подтверждают окончательность начислений, отсутствие внешних расходов и закрытие периода. Прибыль не равна банковской выплате. Для вывода используется отдельно введённый доступный денежный остаток минус резервы налогов, материалов и обязательных платежей. Автоматической банковской сверки нет.

## Повторные отчёты и исправления

В оригинальном отчёте «ID начисления» повторяется для разных услуг, иногда отсутствует. Поэтому он не является уникальным ID финансовой строки. Автоимпорт суммирует строки одного дня/услуги/товара/ссылки и сохраняет их как снимок **полного периода отчёта**. При новой выгрузке ранее импортированные этим способом строки периода атомарно заменяются. Исчезнувшие из полного отчёта операции удаляются, задержанные и исправленные пересчитываются. За пределами периода записи сохраняются. Загружайте полные отчёты и расширяйте период, если исправление перенесено через его границу.

Хеш файла предотвращает повторную загрузку. При повторном выборе того же файла настройки и себестоимость не перезаписываются: изменяйте их отдельно через справочник и настройки. История импортов сохраняется, но сырые файлы не копируются в базу. Если в периоде есть операции ручного импорта, автоимпорт блокируется во избежание двойного учёта. Режим итоговых начислений `net` также нельзя смешивать с детализацией.

Ручной импорт использует постоянные уникальные ID строк из подготовленной таблицы: прежний ID в новом файле обновляет запись. Удаление строки из ручного файла не удаляет её из базы; требуется явная корректировка. У интерфейса пока нет удаления ошибочного ручного импорта — сохраняйте резервную копию.

## Запуск для разработчика

Рабочая папка `/workspace/Ozon_calc`. Используйте существующий checkout: облачная задача уже изолирована, отдельный Git worktree не нужен.

```bash
python3 -m venv /workspace/ozon-venv
/workspace/ozon-venv/bin/python -m pip install -r requirements-dev.txt
/workspace/ozon-venv/bin/python -m pytest -q
/workspace/ozon-venv/bin/python launcher.py
```

`launcher.py` применяет адрес 127.0.0.1, выбирает свободный порт, запускает сервер и после проверки готовности открывает браузер. Телеметрия отключена. Дополнительные сервисы не нужны. Для установки нужен PyPI. После восстановления облачной среды процесс нужно запускать заново. Локальный адрес не является ссылкой облачного предпросмотра.

## Windows 10/11

Подготовлен `.github/workflows/windows.yml`: Windows, Python 3.12, тесты, PyInstaller, проверка запуска EXE и архив-артефакт. Workflow ещё не выполнен на Windows; готовый проверенный EXE пока не опубликован.

После размещения исходников на GitHub: **Actions → Windows application → Run workflow → Run workflow**. Дождитесь зелёного результата; в **Artifacts** нажмите **OzonProfit-Windows**. Распакуйте весь архив и откройте **OzonProfit.exe**. Самостоятельно устанавливать Python не нужно. Если сборка завершилась ошибкой, её нужно исправить до передачи программы пользователю. Для приватных репозиториев учитывайте лимиты Actions.

База Windows: `%LOCALAPPDATA%\OzonProfit\profit.db`, Linux: `~/.local/share/OzonProfit/profit.db`. Разработчик может указать папку через `OZON_PROFIT_DATA_DIR`. База сохраняется между запусками и отдельно от архива программы. Закройте программу перед копированием базы. Закрытие вкладки браузера сервер не завершает — нужно закрыть консольное окно.

## Защита данных и следующие этапы

Реальные Excel, базы, финансовая сверка и ключи не включаются в исходники/архив кода. В публичных тестах используются только вымышленные суммы. SQLite не зашифрована: защищайте личную папку, учётную запись и диск. Не публикуйте личный отчёт со сверкой. Приложение не пишет финансовые строки в журнал. Сообщения ошибок импорта могут показывать проблемное значение на локальном экране.

Экспериментальное подключение Seller API добавлено в раздел «Подключение Ozon»: загрузка финансов и FBO/FBS-отправлений, проверка страниц, повторные попытки, сохранение снимков и добровольное расписание. В Windows ключ можно сохранить через DPAPI, в Linux он остаётся в памяти. Прибыль пока считается по Excel: API-данные показываются отдельно для сверки. Актуальная документация и ответы реального магазина недоступны из этой среды, поэтому подключение не объявляется завершённым. Подробности и необходимые сетевые разрешения — в [API_STATUS.md](API_STATUS.md).

После проверки документации и реальных ответов — согласование финансового источника для автоматического расчёта прибыли, затем запуск Windows workflow и проверка скачанной программы на Windows. Готовый Windows-релиз пока не опубликован.

## Веб-версия

Порядок размещения: [WEB_DEPLOY.md](WEB_DEPLOY.md). Ветка `main`, файл `app.py`, Python 3.12. По умолчанию действует обязательный вход через `app_password` в Secrets сервиса. Без настроенного пароля база не открывается. Локальный launcher явно включает desktop-режим. Не включайте `OZON_PROFIT_LOCAL` при облачном размещении. Данные облачной SQLite могут потеряться при пересоздании сервера; сохраняйте резервные копии. Веб-публикация и проверка доступности по внешней ссылке требуют действий владельца в Streamlit и пока не подтверждены.
