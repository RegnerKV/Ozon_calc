# Ozon Profit 💎

Приложение для Windows 10/11 с русским интерфейсом в локальном браузере. Python и платный хостинг пользователю не нужны. База, стоимость товаров, история, настройки и план сохраняются в личной папке Windows; ключ Ozon защищён DPAPI текущего пользователя.

## Четыре раздела

- **Обзор**: прибыль, реализация, начисления Ozon, стоимость, налог, реклама, рентабельность, динамика и результат товаров. Основная кнопка — «Обновить». Операции и ручные денежные резервы спрятаны в раскрывающиеся блоки.
- **Товары**: однократная загрузка Себестоимость.xlsx, история стоимости и редактирование. Сохранённая библиотека применяется к новым товарам; ручные значения не перезаписываются автоматически.
- **План продаж**: срок, товары, количество и прогноз чистой прибыли. Отдельно — увеличение рекламной доли в процентных пунктах. План сохраняется автоматически и не меняет реальные операции.
- **Настройки**: однократное подключение Ozon, обновления и налоги. Диагностика и прежние способы импорта доступны в дополнительных инструментах.

## Первый запуск Windows

Готовая проверенная beta-сборка: [OzonProfit-Windows.zip](https://github.com/RegnerKV/Ozon_calc/releases/download/v0.2.0-beta.5/OzonProfit-Windows.zip), около 113 МБ. Проверка Windows: [workflow](https://github.com/RegnerKV/Ozon_calc/actions/runs/41587345232). Распакуйте весь архив и дважды нажмите OzonProfit.exe. В настройках один раз введите Client ID и ключ Seller API на чтение, в товарах один раз загрузите себестоимость и проверьте дату. Дальше данные подхватываются автоматически.

Приложение хранит базу в `%LOCALAPPDATA%\OzonProfit\profit.db`, отдельно от папки EXE. Повторный запуск открывает уже работающий экземпляр. Закрытие вкладки не останавливает сервер; для завершения закройте консольное окно. Сборка не подписана цифровой подписью. Используйте собственный проверенный релиз, не отключайте защиту Windows.

## Расчёт и пределы

Начисления = сумма финансовых операций со знаком; предварительная прибыль = начисления − стоимость проданных изделий − налоговый резерв. По API покупательская реализация выделяется из sale_amount за вычетом bonus/coinvestment. Возмещения, итоговые комиссии и доставка не учитываются дважды. Каждый accrual_id обязан сойтись по сумме. При неизвестном составе или количестве предыдущая прибыль сохраняется, новая не подставляется корректировкой. Без стоимости активация расчёта блокируется; оценочная стоимость явно отмечается.

Налоговые настройки предварительные, не являются расчётом ФНС. Прибыль не равна банковскому остатку и доступным деньгам для вывода. Сумма вывода определяется отдельно по фактическому остатку и резервам. Возврат выручки не означает восстановление физического товара в запасе. Основной учёт ведётся по датам начислений, общие расходы не распределяются по заказам автоматически.

Прогноз использует среднюю реализацию, возмещения и удержания по истории, стоимость на начало плана, общий процент рекламы и налоги. Реклама исключается из исторического вклада и добавляется в сценарий ровно один раз. Для нового товара нужна ожидаемая цена; при отсутствии собственной истории используются средние условия магазина с отметкой оценки. Разовые компенсации/корректировки не переносятся в будущие продажи. Срок определяет темп, не умножает прибыль на количество дней. Это сценарий, не прогноз спроса.

## Разработчику

Существующий checkout `/workspace/Ozon_calc`; отдельный worktree не нужен.

```bash
python3 -m venv /workspace/ozon-venv
/workspace/ozon-venv/bin/python -m pip install -r requirements-dev.txt
/workspace/ozon-venv/bin/python -m pytest -q
/workspace/ozon-venv/bin/python launcher.py
```

Локальный сервер слушает только 127.0.0.1; телеметрия отключена. Web-режим по умолчанию требует app_password в Streamlit Secrets. На Linux ключ сохраняется зашифрованно с использованием этого пароля. Для постоянства после полной пересборки Community Cloud подготовлено опциональное приватное хранилище Supabase с зашифрованной копией SQLite; реальное подключение Supabase требует реквизитов владельца. В Windows Supabase не нужен. Пользовательские резервные копии исключают даже зашифрованный ключ API.

Workflow Windows application запускает тесты, PyInstaller и браузерную проверку настоящего EXE: экраны, DPAPI, единственный экземпляр, план и повторный запуск. ZIP публикуется как предварительный GitHub Release только после этих проверок. Не считайте один файл workflow доказательством успешной сборки: фактический результат указан в отчёте задачи.

Технические подробности: API_STATUS.md, API_MIGRATION.md, API_PROFIT.md, VALIDATION.md. Реальные Excel, базы, ключи и финансовые результаты не входят в исходники или релиз. Публичные тесты и скриншоты сборки используют вымышленные данные.

## Ошибка соединения с Ozon

Windows-сборка beta.3 использует системное хранилище доверенных сертификатов
Windows с обязательной проверкой HTTPS. Ошибки сертификата, прокси и тайм-аутов
показываются отдельно, без текста исключений, ключей и содержимого запросов.
В настройках доступна отдельная проверка соединения без импорта данных.
При обновлении закройте консоль старой версии и распакуйте новый архив целиком
в отдельную папку. Локальная база и ключ остаются в прежнем месте.

Проверка сборки выполняется на вымышленных данных; она подтверждает работу EXE,
но не доступность Ozon из сети конкретного пользователя. При неудаче обновления
сообщите безопасный код ошибки и имя метода; сам API-ключ присылать не нужно.

## Данные загружены, но расчёт не завершён

Дашборд рассчитывает выбранный период непосредственно по сохранённым данным API.
Ошибка сопоставления в другом месяце не скрывает доступный период. Это просмотр
без перезаписи учётных операций. Если не хватает исторической себестоимости,
начисления и реализация видны, а прибыль скрыта до уточнения стоимости; таблица
показывает артикул и дату продажи. При несопоставленных начислениях показываются
только исходная сумма начислений API и причины блокировки, без частичной прибыли.
«Последний месяц с данными» определяется по фактическим операциям, а не дате
окончания загрузки пустых дней. Все проверки используют вымышленные данные.

## Принятое владельцем правило для остатков ассортимента

Товары без собственной себестоимости автоматически получают полную стоимость
подвески «Рыба» из сохранённого справочника, включая упаковку. Для старых продаж
используется первое сохранённое значение «Рыбы», последующие изменения стоимости
применяются с соответствующих дат. Это принятое владельцем значение для учёта,
без флага оценочной стоимости; пояснение об источнике сохраняется в истории.
Прежние автоматические оценки по «Рыбе» переводятся на это правило. Собственные
стоимости товаров и другие ручные оценки сохраняются. Если позже задать
собственную стоимость, она имеет приоритет с выбранной даты. При отсутствии
стоимости самой «Рыбы» программа не придумывает число. Правило работает для
новых артикулов при обновлении каталога и для планирования продаж.
