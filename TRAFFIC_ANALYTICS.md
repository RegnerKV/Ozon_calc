# Реклама и общие показы

Новый раздел «Реклама» не меняет финансовые операции и расчёт прибыли.
Все загруженные наблюдения сохраняются в локальной SQLite между запусками;
они также входят в существующую зашифрованную резервную копию.

## Источники и ограничения

* Seller `POST /v1/analytics/data`: metrics `hits_view`, `ordered_units`,
  dimension `sku`, `day`. Это общие показы, не рекламные показы и не
  уникальные посетители. Метрики запрашиваются вместе; если доступ отклонён,
  старые данные сохраняются. По опубликованной схеме `hits_view` ограничен
  подпиской. В приложении выполняется реальный запрос существующим ключом.
  Повторный запрос не чаще минуты; пагинация также соблюдает минутный интервал.
* Performance `GET /api/client/statistics/all_sku_promo/products/generate/json`:
  отчёт истории общего продвижения с оплатой за заказ. UUID сохраняется;
  готовность проверяется отдельным нажатием, без длительного ожидания.
  Загрузка через фиксированный `/api/client/statistics/report?UUID=…`.
  Ссылки из ответа не используются для передачи токена.
* Performance `GET /api/client/campaign` без фильтра текущего состояния:
  включая неактивные и архивные кампании, выбираются только `paymentType=CPC`.
  `GET /api/client/statistics/daily/json`: дневные расходы этих кампаний,
  группами до 10 идентификаторов. Отсутствие расходов не означает выключение.
  Если кампаний не найдено, неизвестная история не заменяется нулями.
* API активации, деактивации и изменения ставки заблокированы транспортом.

Схемы проверены 09.11.2026 по публичной копии OpenAPI
https://github.com/MissiaL/ozon-api/tree/main/references;
официальные разделы https://docs.ozon.ru/api/seller/ и
https://docs.ozon.ru/api/performance/.
В облачной среде нет ключей магазина и разрешённого доступа к хостам Ozon.
Реальные JSON-контейнеры рекламных отчётов недостаточно детализированы в схеме;
поддерживаются массив строк и контейнеры rows/list/data/report, с явными
именами колонок. Неизвестный формат вызывает понятную ошибку без перезаписи
сохранённых данных. Нельзя считать синтетические тесты проверкой кабинета.

## Экран

Период до 62 завершённых дней, весь магазин или SKU. Синяя линия общих
показов, голубые столбцы расходов за клики, лимонный фон включённого общего
продвижения, серый фон разных статусов в один день. Белый фон может означать
выключенный или неизвестный статус — точный статус указан в таблице по дням.
Пустые значения не равны нулю, линия не соединяется через пропуски.

Сравнение четырёх сочетаний общего продвижения и наличия расходов за клики
использует только дни с известными показами, расходами и однозначным статусом.
Показываются размеры групп, средние показы/заказы/расходы. Неполные дни
исключаются с пояснением. Общие расходы кампаний не распределяются на SKU:
для конкретного товара сравниваются только состояния общего продвижения.
Разница средних не доказывает причинное влияние: цены, наличие, дни недели,
прочая реклама и сезонность могут объяснять изменения.

При ограничении Seller API можно импортировать Excel/CSV:
«Дата», «SKU», «Показы (всего)», необязательно «Заказано товаров».
Есть пустой шаблон; импорт обновляет только переданные пары дата/SKU,
не удаляет другие товары. Повторы, отрицательные и дробные количества
отклоняются целиком. Неизвестное число заказов остаётся пустым, а не нулём.
Исходные файлы пользователя в репозиторий не добавляются.
